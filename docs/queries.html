Consultas que carregam o tipo até a linha

O builder transforma referências de coluna em SQL com binds. Queries de tabela completa hidratam DTOs gerados; seleções parciais assumem explicitamente o tipo array<string, mixed>.

Conexão e referência de tabela

use App\Models\Generated\Tables;
use Diogodg\Neoorm\Query\Database;

$db = Database::fromConfig();
$users = Tables::users(); // ou Users::ref()

Database::fromConfig() constrói uma conexão PDO com exceções, prepared statements nativos e UTC como fuso da sessão. O MySQL usa MYSQL_ATTR_FOUND_ROWS, então UPDATE retorna o número de linhas encontradas — igual ao PostgreSQL — mesmo se o valor já fosse igual.

Select

use function Diogodg\Neoorm\Query\eq;

$all = $db->select()->from($users)->all();
$one = $db->select()->from($users)->where(eq($users->id, 1))->one();
$required = $db->select()->from($users)->where(eq($users->id, 1))->oneOrFail();
$total = $db->select()->from($users)->count();

foreach ($db->select()->from($users)->cursor() as $row) {
    // Generator<UsersRow>, sem materializar todas as linhas
}
MétodoRetornoUso
all()list<Row>Materializa o resultado.
one()?RowRetorna null quando não há linha.
oneOrFail()RowExige resultado e lança em caso de ausência.
count()intIgnora ordenação e paginação; respeita o conjunto lógico.
cursor()Generator<Row>Itera em streaming.

Condições e expressões

Operadores são funções e valores são sempre bind parameters. Para combinar condições, use Op::and(), Op::or() e Op::not().

use Diogodg\Neoorm\Query\Op;
use function Diogodg\Neoorm\Query\{between, eq, gte, ilike, inArray, isNotNull, like, ne, notInArray, sql};

$rows = $db->select()->from($users)
    ->where(Op::and(
        gte($users->age, 18),
        Op::or(ilike($users->name, 'a%'), inArray($users->status, ['active', 'trial'])),
        isNotNull($users->email),
    ))
    ->all();

// Fragmento SQL cru; os argumentos ainda viram binds.
$longNames = $db->select()->from($users)
    ->where(sql('LENGTH(name) > ?', 10))->all();

Estão disponíveis eq, ne, gt, gte, lt, lte, like, notLike, ilike, inArray, notInArray, between, notBetween, isNull e isNotNull. ilike() usa ILIKE no PostgreSQL e LOWER(a) LIKE LOWER(b) no MySQL.

Nulidade é explícita. eq($column, null) e ne($column, null) lançam cedo, porque = NULL e <> NULL não são verdadeiros em SQL. Use isNull() ou isNotNull().

Ordenação, paginação e agregação

use Diogodg\Neoorm\Query\Func;
use Diogodg\Neoorm\Query\Expr\{Aliased, NullsPlacement};
use function Diogodg\Neoorm\Query\{asc, desc, gt};

$page = $db->select()->from($users)
    ->orderBy(desc($users->created_at, NullsPlacement::Last), asc($users->name))
    ->limit(20)->offset(40)->all();

$byStatus = $db->selectFields([$users->status, new Aliased(Func::count(), 'total')])
    ->from($users)->groupBy($users->status)
    ->having(gt(Func::count(), 5))->all();

limit() e offset() recusam valores negativos. No MySQL, NULLS FIRST/LAST é compilado como termo adicional com IS NULL para preservar a semântica do PostgreSQL. Em consultas com GROUP BY, HAVING ou DISTINCT, count() conta as linhas resultantes por subconsulta.

Joins e seleção parcial

$posts = Tables::posts();
$rows = $db->selectFields([$users->id, $users->name, $posts->title])
    ->from($users)
    ->leftJoin($posts, eq($posts->author_id, $users->id))
    ->all();

$rows[0]['id'];            // coluna da tabela base
$rows[0]['posts__title'];  // coluna da tabela juntada

O prefixo {tabela}__{coluna} impede que FETCH_ASSOC silenciosamente sobrescreva chaves homônimas. Uma tabela com alias requalifica suas colunas e torna self-joins possíveis:

$neighbor = Tables::users('neighbor');
$db->selectFields([$users->id, $neighbor->id])
   ->from($users)
   ->innerJoin($neighbor, eq($neighbor->manager_id, $users->id))
   ->all();

Insert, update e delete

use App\Models\Generated\Inserts\UsersInsert;

$db->insert($users)
    ->values(new UsersInsert(name: 'Diogo', email: 'd@x.com'))
    ->execute();

$created = $db->insert($users)
    ->values(new UsersInsert(name: 'Ana', email: 'a@x.com'))
    ->returningOne();

$db->update($users)->set(['active' => false])
    ->where(eq($users->id, 1))->execute();
$db->delete($users)->where(eq($users->id, 1))->execute();

returningOne() usa RETURNING no PostgreSQL e lastInsertId() seguido de select no MySQL. Campos de Insert que têm DEFAULT ou auto incremento são opcionais: null omite a coluna, para o banco usar o próprio padrão. Em lote, campos opcionais omitidos em apenas algumas linhas viram DEFAULT nessas linhas.

Proteção contra escrita acidental: UPDATE e DELETE sem where() são recusados. Para o caso intencional, declare-o com allowFullTableScan() antes de execute().

Builders imutáveis e transações

$active = $db->select()->from($users)->where(eq($users->active, true));
$firstPage = $active->limit(20)->all();
$total = $active->count(); // $active não foi alterado

$db->transaction(function (Tx $tx) use ($users, $posts) {
    $author = $tx->insert($users)->values(new UsersInsert(name: 'Ana'))->returningOne();
    $tx->insert($posts)->values(new PostsInsert(author_id: $author->id, title: 'Olá'))->execute();
});

Cada cláusula retorna um novo builder. Transações aninhadas criam savepoints reais; uma falha interna volta até o savepoint sem desfazer o trabalho externo. Tx e Database implementam Executor, portanto repositórios podem depender dessa interface.

Inspecionar SQL

$compiled = $db->select()->from($users)->where(eq($users->id, 1))->toSql();

$compiled->sql;      // SQL com :p0, :p1…
$compiled->values(); // ['p0' => 1]
