Descreva a tabela uma vez

O schema fica no método estático table(). Cada coluna é um valor imutável e o model é validado antes de migrar ou gerar tipos.

Colunas e modificadores

Table::columns() recebe um mapa nome => Col. Isso impede que o nome seja repetido no construtor e elimina divergência entre chave e coluna. As fábricas cobrem os tipos comuns e Col::type('...') existe como escape para tipos específicos.

return Table::make('product')
    ->columns([
        'id'       => Col::bigId(),
        'sku'      => Col::varchar(32)->notNull()->unique(),
        'price'    => Col::decimal(19, 4)->notNull()->default(0),
        'metadata' => Col::json(),
        'enabled'  => Col::boolean()->notNull()->default(true),
    ]);

Os modificadores disponíveis são notNull(), nullable(), primary(), unique(), autoIncrement(), unsigned(), index(), default(), defaultRaw(), defaultNull(), comment(), collation() e references().

$money = Col::decimal(19, 4)->notNull()->default(0);

'balance' => $money,
'credit'  => $money->comment('Credit limit'), // $money não muda

Chaves, índices e relações

Regras que abrangem mais de uma coluna pertencem à tabela. A ordem das chamadas não muda o resultado: a validação ocorre sobre o schema final em build().

return Table::make('product_category')
    ->columns([
        'product_id'  => Col::int()->notNull(),
        'category_id' => Col::int()->notNull(),
        'score'       => Col::decimal(3, 1),
    ])
    ->primary(['product_id', 'category_id'])
    ->unique('product_category_score_unique', ['product_id', 'score'])
    ->index('product_category_score_index', ['score'])
    ->check('score >= 0')
    ->foreignKey('category', ['category_id'], ['id'])
    ->timestamps();

Para relação de uma só coluna, prefira references(OtherModel::class). A classe é verificável estaticamente e dá ao NeoORM o nome correto da tabela declarada no outro model.

Models em subpastas

O diretório de models é percorrido recursivamente. A subpasta vira um segmento de namespace pela regra PSR-4 e o diretório Generated/ é ignorado pelo loader.

App/Models/
  Country.php                 # App\Models\Country
  Billing/Invoice.php         # App\Models\Billing\Invoice
  Generated/                  # ignorado

O que o gerador entrega

generate:types cria tabelas com propriedades de coluna, DTOs readonly de linha, payloads de insert e enums PHP. As propriedades preservam o nome exato da coluna em snake_case; transformar nomes para camelCase criaria colisões ambíguas.

$u = Tables::users();
$u->email; // ColumnRef conhecida pela IDE

$row = $db->select()->from($u)->one();
// ?UsersRow; $row?->created_at é DateTimeImmutable

Inclua o gerado no versionamento. Ele é código-fonte revisável. Use generate:types --check como gate de CI para impedir que models e tipos se afastem.

Seeders

Dados iniciais vivem em PATH_SEEDS, um seeder por tabela. A separação deixa claro que mudanças de dados e de schema têm ciclos distintos.

final class CountrySeeder extends Seeder
{
    public static function table(): string { return Country::table; }

    public function run(Executor $db): void
    {
        if ($db->select()->from(Tables::country())->count() > 0) {
            return;
        }

        $db->insert(Tables::country())
            ->values(new CountryInsert(name: 'Brasil'))
            ->execute();
    }
}

db:seed executa seeders na ordem do grafo de chaves estrangeiras e dentro de uma transação. Cada seeder deve ser idempotente: o runner não registra execuções anteriores. Se houver duas classes para uma tabela, ou um seeder apontar para tabela inexistente, o comando falha com a lista de problemas.

vendor/bin/neoorm db:seed
vendor/bin/neoorm db:seed --tables=country,state
