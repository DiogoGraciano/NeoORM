Introdução

Comece com um schema pequeno e verificável

Em NeoORM, você declara tabelas como classes PHP, gera as referências tipadas e então consulta por meio de uma conexão explícita. O processo não depende do banco até a hora de aplicar a migração.

Requisitos

  • PHP 8.4 ou superior;
  • as extensões pdo, json e mbstring;
  • MySQL ou PostgreSQL quando for executar migrações ou consultas.

1. Instale o pacote

composer require diogodg/neoorm

O executável instalado pelo Composer fica em vendor/bin/neoorm. Em um projeto NeoFramework, os mesmos comandos também estão disponíveis com php neof.

2. Configure o ambiente

Crie um .env na raiz do projeto. A biblioteca procura a raiz pelo composer.json; por isso os caminhos relativos abaixo são estáveis mesmo se o CLI for executado de uma subpasta.

DRIVER=mysql                 # mysql ou pgsql
DBHOST=localhost
DBPORT=3306
DBNAME=app
DBUSER=root
DBPASSWORD=
DBCHARSET=utf8mb4            # MySQL
DBSCHEMA=public              # PostgreSQL; opcional

# Estas chaves são opcionais; os valores mostrados são os padrões.
PATH_MODEL=./App/Models
MODEL_NAMESPACE=App\Models
PATH_GENERATED=./App/Models/Generated
GENERATED_NAMESPACE=App\Models\Generated
PATH_SEEDS=./App/Seeders
SEEDER_NAMESPACE=App\Seeders
PATH_MIGRATIONS=./Migrations
MIGRATIONS_TABLE=_neoorm_migrations
MIGRATIONS_STRICT=true
ENVIRONMENT=dev

Precedência: uma variável em $_ENV ou $_SERVER vence o valor do arquivo .env. Uma chave de caminho ou namespace vazia, como PATH_MODEL=, usa o padrão.

3. Declare um model

O model é a fonte de verdade do schema. Ele não é Active Record: não representa uma linha, não possui get() ou store() e não conecta ao banco quando table() é chamado.

<?php

namespace App\Models;

use App\Models\Generated\UsersTable;
use Diogodg\Neoorm\Abstract\Model;
use Diogodg\Neoorm\Migrations\Col;
use Diogodg\Neoorm\Migrations\Table;

/** @extends Model<UsersTable> */
final class Users extends Model
{
    public const table = 'users';

    public static function table(): Table
    {
        return Table::make(self::table, comment: 'Application users')
            ->columns([
                'id'         => Col::id(),
                'name'       => Col::varchar(120)->notNull(),
                'email'      => Col::varchar(255)->notNull()->unique(),
                'active'     => Col::boolean()->notNull()->default(true),
                'created_at' => Col::timestamp()->notNull(),
            ]);
    }
}

A anotação @extends Model<UsersTable> dá o tipo concreto a Users::ref(). Ela referencia um arquivo que ainda não existe de propósito: o gerador precisa carregar os models antes de criar Generated/.

4. Gere o código tipado

vendor/bin/neoorm generate:types

Esse comando lê os models e cria, no diretório configurado em PATH_GENERATED:

App/Models/Generated/
  Tables.php              # Tables::users()
  UsersTable.php          # propriedades de coluna tipadas
  Rows/UsersRow.php       # linha readonly hidratada
  Inserts/UsersInsert.php # payload de insert por argumentos nomeados
  Enums/...               # enum PHP quando há coluna ENUM

Não há conexão nessa etapa. Comite esse diretório junto aos models e verifique-o no CI:

vendor/bin/neoorm generate:types --check

--check não escreve arquivos e retorna código 1 quando houver drift no código gerado ou na anotação @extends.

5. Versione e aplique o schema

vendor/bin/neoorm migration:generate --name=initial
vendor/bin/neoorm migration:up
vendor/bin/neoorm db:check

O primeiro comando gera SQL e snapshots dentro de Migrations/mysql/ ou Migrations/pgsql/, sem abrir conexão. O segundo aplica as migrações pendentes. O terceiro confere se models, snapshot e banco estão em acordo.

6. Faça uma consulta

<?php

use App\Models\Generated\Tables;
use Diogodg\Neoorm\Query\Database;
use function Diogodg\Neoorm\Query\{eq, desc};

$db = Database::fromConfig();
$users = Tables::users();

$active = $db->select()->from($users)
    ->where(eq($users->active, true))
    ->orderBy(desc($users->created_at))
    ->limit(20)
    ->all(); // list<UsersRow>

A partir desse ponto, $active[0]->email é uma propriedade conhecida pela IDE e pelo PHPStan. Veja Consultas para filtros, joins, escrita e transações.

Produção: mantenha ENVIRONMENT=prod. Nesse modo, db:push e db:reset são bloqueados. Aplique somente o histórico de migrações revisado.
